# AI課金・原価管理ガイド（Free/Pro運用案）

## 目的

本ドキュメントは、HomTune の AI 機能を黒字運用するために、以下を定義します。

- 実際の利用料・請求の確認方法
- インフラ側での強制制御ポイント
- Free / Pro の価格と利用上限（運用案）

---

## 1. 実際の利用料・請求を確認するベストプラクティス

## 結論

最も安全なのは、**請求の真実はクラウド請求基盤で確認し、アプリ側は推定値でUX制御する二層構成**です。

- 正式な請求: クラウドベンダーの Billing（Google Cloud Billing 等）
- 体験制御: `AiUsageService` の推定クレジット/推定コスト

## 推奨運用

1. **Billing予算アラート**
   - 月次予算に対して 50% / 75% / 90% / 100% の通知を設定
   - 100% 到達時は運用アラートを Pager/Slack に即時通知

2. **日次の原価可視化**
   - 課金データを BigQuery（または同等）にエクスポート
   - 機能別（chat / roomImage / scanner / maintenance）に日次集計
   - 指標:
     - `cost_per_active_user`
     - `cost_per_paid_user`
     - `feature_cost_share`

3. **アプリ内推定値との差分監視**
   - `AiUsageService` の推定合計と請求実績の差分率を週次確認
   - 差分が 15% を超えたら `creditCost` パラメータを再調整

## 2. インフラ構築側での制御は可能か

可能です。むしろ**本番では必須**です。

## 必須制御（本番）

1. **APIキーをアプリに持たせない**
   - 現在は `--dart-define=GEMINI_API_KEY` の直利用が可能だが、本番では禁止
   - クライアント → 自社API → LLM のサーバープロキシに変更

2. **サーバー側クォータゲート**
   - ユーザーIDとプランで判定し、上限超過時は `402/429` を返す
   - アプリはローカル回答へフォールバック

3. **レート制限**
   - 例: `chat: 20 req / 10 min`, `roomImage: 3 req / day (Free), 12 req / month (Pro)`
   - ボット/誤爆による原価急増を防止

4. **強制キルスイッチ**
   - 月次実コストが閾値超過時、機能単位で AI を即停止
   - `roomImage` のみ停止、`chat` は継続など粒度制御

5. **監査ログ**
   - 誰がいつどの機能を実行したかを保存（請求問い合わせ対応）

## 推奨制御（拡張）

- モデル自動切替（高負荷時は低単価モデル）
- キャッシュ（同一質問・同一文脈の再生成抑制）
- 非同期バッチ化（重い処理を即時応答から分離）

## 3. Free / Pro の価格・利用制限（策定案）

以下は現行の `AiUsageService` / `AiUsagePolicy` を前提にした運用案です。

## 価格

| プラン | 月額（税込） | 想定ユーザー |
|---|---:|---|
| Free | 0円 | 試用・ライトユーザー |
| Pro | 490円 | 画像生成も使う日常ユーザー |

## 利用上限（推奨）

| 項目 | Free | Pro |
|---|---:|---:|
| 月間AIクレジット | 40 | 120 |
| AIチャット | 5〜10 回/月 | 40〜60 回/月 |
| AI部屋画像生成 | **アカウント生涯1回**（1部屋体験・他はデフォルト） | 2回/部屋/月 |
| AIスキャン補正 | 0〜3 回/月 | 5〜10 回/月 |
| AIメンテ文生成 | 0〜2 回/月 | 5 回/月 |
| 上限超過時 | ローカル応答へ自動フォールバック | 追加クレジット購入導線を表示 |

## 追加クレジット（ハイブリッド課金）

| 追加パック | 価格（税込） | 用途 |
|---|---:|---|
| 50 credits | 350円 | 画像生成やチャットの不足分補填 |
| 120 credits | 780円 | 画像生成を多用する月向け |

## 部屋画像の原価メモ（2026-07 更新）

- 実装: Gemini でスタイル JSON のみ生成 → **端末内で PNG 合成**（Imagen 等の画像生成 API は未使用）
- 課金: **2 credits/回**、推定 **~$0.024/回**（`roomImageCreditCostUsd = 0.012`）
- 旧設計（8cr × $0.05 = $0.40）は実装と乖離しており廃止


- 目標粗利率: **60%以上**
- 監視すべき比率: `実コスト / 課金売上`
  - 0.40 以下: 健全
  - 0.40〜0.55: 要監視
  - 0.55 超: 価格または上限を即調整

## 4. 現実装へのマッピング

- 実装済みの主要要素
  - `AiRoutingService`: ローカル優先ルーティング（`LocalResponsePlanner` の信頼度と連携）
  - `LocalResponsePlanner` / `DeviceQueryMatcher`: ローカル回答可能判定とデバイスマッチ
  - `ChatRoutePreviewBuilder`: 送信前の「次の回答: ローカル/AI」表示
  - AI確認ダイアログ: Freeは常に確認、Proはローカル不可かつ2cr以上（またはAI必須）のみ
  - `AiUsageService`: クレジット消費/予算判定
  - `AnalyticsService`: 利用イベント記録
  - `ChatWidget`: AI実行前確認、残量表示、フォールバック
  - `RoomImageGenerationService`: AI部屋画像生成 + 消費記録

- 次段階（本番前に必須）
  - サーバープロキシ化（キー秘匿）
  - サーバー側クォータDB（プラン別制御）
  - 決済連携（StoreKit/Play Billing + サーバー検証）

## 4.1 推奨モデル（2026-06時点）

- 現在実装での最小コスト運用モデルは **`gemini-3.1-flash-lite`** を採用
- 対象機能:
  - 質問チャット
  - スキャンOCR後の構造化抽出
  - メンテ文生成
  - 部屋画像スタイル仕様生成
- 理由:
  - `gemini-2.0-flash-exp` は実験系で長期運用リスクがある
  - Flash-Lite はコスト重視の高トラフィック向け

## 5. 運用チェックリスト（月次）

1. 実請求と推定コスト差分を確認（差分15%以内）
2. プラン別ARPPUとAI原価を確認
3. `roomImage` の原価寄与率を確認（高ければ上限調整）
4. 上位5%ヘビーユーザーの濫用パターンを確認
5. 翌月の価格/上限を更新

## 6. 実請求ベース自動調整（実装済み）

`BillingControlService.autoTuneFromActualBilling()` で、実コストをもとに翌月の Pro 上限を自動調整します。

- 入力:
  - `actualCostUsd`（実請求）
  - `proSubscriberCount`（有料会員数）
  - `fxJpyPerUsd`（為替）
- 固定値:
  - Pro価格: 490円
  - 目標原価率: 45%
- 係数:
  - `scale = clamp(targetCostUsd / actualCostUsd, 0.5, 1.1)`
- 調整対象:
  - `proMonthlyCredits`
  - `proRoomImagePerRoomMonthly`
  - `softMonthlyCostWarnUsd`
  - `hardMonthlyCostCapUsd`

これにより、実請求が重い月は自動で上限縮小し、余裕がある月は段階的に緩和できます。
