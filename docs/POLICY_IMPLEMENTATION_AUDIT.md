# 目標KPI vs 現行実装ギャップ監査

最終更新: 2026-07-13  
対象ブランチ: `cursor/gemini-proxy-prep-41d3`  
基準KPI: Free＝AI部屋画像1回体験＋デフォルト運用／Pro訴求、500 MAU・転換率≥5%、Pro平均AI≤$0.90、Free利用≤枠の35%

---

## 総合判定

| 領域 | 判定 |
|------|------|
| Free AI部屋画像（クライアント） | **概ね合致**（アカウント生涯1回） |
| 「デフォルト＋変更時Pro」ファネル | **不十分**（実写カスタムが無料のまま） |
| Free 原価抑制（ローカル優先） | **チャットのみ合致**／スキャン・メンテは漏れやすい |
| サーバー強制・課金検証 | **未達（リリース blocker）** |
| ドキュメント整合 | **一部旧表記残存 → 本PRで修正** |

結論: **コアの「1部屋AIお試し」クライアント実装は理にかなっているが、転換・原価の両KPIに対し修正必須ポイントが複数ある。** 特に「写真カスタム無料」「プロキシ既定でFreeクラウド全開」「サーバー未強制」は目標と矛盾。

---

## 合致している点（維持）

1. **Free AI部屋画像 = アカウント1回** — `AiUsageService.canRunRoomImage` が lifetime 合計でゲート。別部屋も拒否。枯渇時 Pro ダイアログ。
2. **Plan / Pro ダイアログ文言** — 「1部屋・1回」に更新済み。
3. **L1/L2・リモコンの Pro ゲート（クライアント）** — Free から機能ロック。
4. **広告は Free のみ表示ロジック** — `AdPolicy.shouldShowFor`。
5. **月次クレジット 40 / 120** — クライアント・サーバー定数一致。
6. **チャット local-first + Free 確認** — 高信頼ローカルは AI を使わない。

## 修正が必要なポイント（優先順）

### Blocker（リリース前必須）

| ID | 問題 | 根拠 | あるべき姿 |
|----|------|------|------------|
| B1 | Free 部屋AI生涯1回が**サーバー未強制** | `backend/lib/ai_quota.js` は月次クレジットのみ。prefs 改ざん・再インストールで再実行可 | `roomImage` に userId 単位 lifetime=1 を DB/永続で強制 |
| B2 | Pro が **`X-HomTune-Pro` 自己申告** | `AiApiClient` / `server.js` | レシート検証後のサーバー tier を正とする |
| B3 | **クレジット二重計上** | プロキシ減算 + クライアント `recordUsage` | サーバー `usage` を正、ローカルは同期のみ |
| B4 | **IAP未接続** | 転換≥5%を収益化できない | Pro / 追加クレジット本番課金 |

### High（KPI直撃・直近修正推奨）

| ID | 問題 | 根拠 | あるべき姿 |
|----|------|------|------------|
| H1 | Free が**カメラ/ギャラリーで全部屋カスタム可能** | `room_photo_setup_screen._pickImage` に Pro ゲートなし | 「変更したい→Pro」なら写真変更も upsell。または政策を「AIのみ課金・実写はFree可」と**明文化してコードと一致** |
| H2 | セットアップ導線が**AI/撮影を強く誘導** | ウェルカム・コーチ・写真後「AIで整える」SnackBar | Freeは「このままでOK」優先。AIは1回明示トライアル、使用後は Pro CTA |
| H3 | `preferAiProxy=true` 既定で Free も**スキャン/メンテがクラウド課金しやすい** | scanner / maintenance はクラウドONで自動消費。chat以外に local-first が弱い | Free: ローカル抽出/テンプレ優先。クラウドは確認 or 月次キャップ（例 scan 1回） |
| H4 | **RoomFairUse（Free5/Pro10）がUI未配線** | サービスはあるが画面から未使用（onboardingが偶然≤5） | 部屋追加UI接続＋超過時 Pro 訴求 |
| H5 | README / FREE_PRO / AI_PRICING が「**1回/部屋**」のまま | 実装と乖離 | 「アカウント生涯1回」に統一（**本ブランチで修正済**） |

### Medium

| ID | 問題 | あるべき姿 |
|----|------|------------|
| M1 | AIボタンが使用後も同じ入口のまま | 不可時は「Proで再生成」に置換（事前 `canRunRoomImage`） |
| M2 | リネーム等の変更に Pro soft-sell がない | 必須ではないが、写真変更とセットで設計 |

| M5 | `freeRoomImageLifetimePerRoom` レガシーフィールド残存 | deprecate / 削除して混乱防止 |

### Low

| ID | 問題 | あるべき姿 |
|----|------|------------|
| L1 | コーチ「部屋の写真を作成」が生成連想 | 「デフォルトで使える／Proでカスタム」へ |
| L2 | ユニットエコ試算が Pro 上限偏重 | Free 平均利用率シナリオを試算に追加 |

## 政策の分岐（要意思決定）

目標文「**それ以外はデフォルト設定で、変更したいときに Pro**」をどう解釈するかで H1 の直し方が分かれる。

| 案 | 内容 | 転換 | Free原価 |
|----|------|------|----------|
| **A（厳格・推奨）** | 部屋カード見た目の変更（AI・実写とも）は Pro。Freeはサンプル固定 | 強い | 最低 |
| **B（現状寄せ）** | AIのみ1回制限。実写カスタムは Free 可 | 弱い | 低（AI以外$0） |

現コードは **B寄り実装 + A寄りのコピー** でねじれている。どちらかに揃えること。

## 500人KPIに対する実装リスク

| KPI | リスク |
|-----|--------|
| 転換 ≥5% | 実写無料・強い撮影CTAで「もう十分」になりやすい（H1/H2） |
| Free利用 ≤35% | プロキシ既定＋scan/maintenance で枠を食いやすい（H3） |
| 部屋AI ≤20%/月 | UXがトライアルを煽ると超過しやすい（H2） |
| Pro平均AI ≤$0.90 | サーバーCapなし・二重計上で監視不能（B1–B3） |
| 広告ARPU $0.12 | 本番AdMob未設定なら売上側も未達（M4） |

---

## 推奨修正順

1. **政策決定**: A（見た目変更はPro）か B（AIのみ）か  
2. **B1–B3** サーバー真実化（quota / tier / 単一計上）  
3. **H1–H3** Free 導線・クラウド抑制を政策に合わせて実装  
4. **H4–H5 / M1** FairUse配線・文言・使用後CTA  
5. **B4 / M4** IAP・AdMob でKPIをクローズ

本監査の次アクションは、政策 A/B の確認後に H1 から着手するのが最短。
