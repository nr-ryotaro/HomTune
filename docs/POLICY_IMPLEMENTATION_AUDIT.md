# 目標KPI vs 現行実装ギャップ監査

最終更新: 2026-07-14  
対象ブランチ: `cursor/room-image-ai-only-41d3`（政策決定後）  
基準KPI: Free＝AI部屋画像1回体験＋デフォルト運用／Pro訴求、500 MAU・転換率≥5%、Pro平均AI≤$0.90、Free利用≤枠の35%

---

## 政策決定（確定）

**B案寄り＋実写なし**

| 項目 | 決定 |
|------|------|
| 部屋カード画像の供給 | **デフォルトasset または AI生成のみ** |
| 実写（カメラ／ギャラリー） | **採用しない**（部屋カード用） |
| Free AI部屋画像 | **アカウント生涯1回** |
| 他部屋・再生成 | **Pro** |

旧A/Bねじれは解消。以降の実装はこの表を正とする。

---

## 総合判定

| 領域 | 判定 |
|------|------|
| Free AI部屋画像（クライアント） | **合致**（アカウント生涯1回） |
| 「デフォルト＋AI生成、実写なし」 | **本PRでUI統一** |
| Free 原価抑制（ローカル優先） | **チャットは合致**／スキャン・メンテは引き続き要注意 |
| サーバー強制・課金検証 | **未達（リリース blocker）** |
| ドキュメント整合 | **政策に合わせて更新** |

結論: **製品方針は確定。クライアントの部屋イメージ導線はAI生成1回体験に揃えた。** サーバー lifetime / Pro tier / 二重計上 / IAP は引き続き blocker。

---

## 合致している点（維持）

1. **Free AI部屋画像 = アカウント1回** — `AiUsageService.canRunRoomImage`
2. **部屋セットアップは実写ボタンなし・AI生成＋デフォルト** — `RoomPhotoSetupScreen`
3. **オンボーディング／ホームコピーもAI・デフォルト前提**
4. **L1/L2・リモコンの Pro ゲート、広告 Free のみ**
5. **月次クレジット 40 / 120**、チャット local-first

## 残りの修正ポイント（優先順）

### Blocker（リリース前必須）

| ID | 問題 | あるべき姿 |
|----|------|------------|
| B1 | Free 部屋AI生涯1回が**サーバー未強制** | `roomImage` に userId 単位 lifetime=1 を永続強制 |
| B2 | Pro が **`X-HomTune-Pro` 自己申告** | レシート検証後のサーバー tier |
| B3 | **クレジット二重計上** | サーバー `usage` を正、ローカルは同期のみ |
| B4 | **IAP未接続** | Pro / 追加クレジット本番課金 |

### High

| ID | 問題 | あるべき姿 |
|----|------|------------|
| H2 | AIトライアル導線の強さは緩和済みだが、試用率モニタは必要 | 目標トライアル≤20%/月を計測で確認 |
| H3 | Free scan/maintenance がクラウド課金しやすい | Free: ローカル優先／確認ダイアログ or 月次キャップ |
| H4 | RoomFairUse（Free5/Pro10）がUI未配線の可能性 | 部屋追加に接続＋超過時 Pro |

### Medium / Low

| ID | 問題 | あるべき姿 |
|----|------|------------|
| M1 | 使用後も同じ「再生成」入口 | Free枯渇時はラベルを「Proで再生成」に |
| M3 | Hard Cap がクライアント寄り | サーバー Hard Cap |
| M4 | AdMob 本番ID・eCPM未計測 | 実測ARPUへ |
